1.App Telemetry (Successful)

	The curl against :8080/metrics returned exactly what it should.
	Your Go/Gin app is actively counting the requests (25 on /api/load/cpu and 138 on /api/workload)
	and successfully formatting them for Prometheus.

	curl -s http://localhost:8080/metrics | grep workload_http_requests_total

2. PromQL Query (Label & Time Window Correction)

	To verify the data is in Prometheus without worrying about the 1-minute window,
	query the raw counter instead:

	curl -s -g 'http://localhost:9090/api/v1/query?query=workload_http_requests_total{namespace="workload-system"}'

	Verification: This will return the exact 25 and 138 counts you saw in Step 1,
	proving Prometheus successfully ingested them.

3. Prometheus Targets

	Prometheus returns its active targets as one massive, single-line JSON payload.
	When you used grep, it matched target-workload but printed the entire block containing
	every system component (like kubernetes-api-servers).

	curl -s -g 'http://localhost:9090/api/v1/targets?match_target={app="target-workload"}'
	curl -s 'http://localhost:9090/api/v1/targets' | grep -i target-workload

4. Grafana Datasource

	curl -s -u admin:prom-operator http://localhost:3000/api/datasources

	Short version

	curl -s -g 'http://localhost:9090/api/v1/targets?match_target={app="target-workload"}' | jq '.data.activeTargets[] | {instance: .labels.instance, health: .health}'
