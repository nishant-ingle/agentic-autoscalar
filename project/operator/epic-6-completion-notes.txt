# EPIC-6: Deterministic Guardrails & Safety Barrier Completion Notes

## Summary of Implementation

We have fully implemented **EPIC-601: Implement Deterministic Guardrail Pipeline in Go Controller** end-to-end to enterprise systems engineering standards.

The deterministic guardrail pipeline acts as an inviolable safety barrier directly inside the Go Kubernetes controller reconciliation loop. It intercepts all AI/LLM recommendations generated by the FastAPI / LangGraph Reasoner, rigorously tests them against hard invariants, and enforces safe bounds, anti-flapping hysteresis, and reactive HPA fallbacks before applying any change to target deployments.

---

### Detailed Architectural Components

#### 1. CRD Schema & API Extensions (`api/v1alpha1/agenticautoscaler_types.go`)
- **Spec Extensions**:
  - `ScaleDownHysteresisSeconds` (`*int32`, default: `600`): Defines the cool-down window (in seconds) rejecting any scale-down request following a prior scale-up event.
  - `TargetCPUUtilization` (`*int32`, default: `70`): Target CPU percentage used for standard reactive HPA fallback calculations during external reasoning outages.
  - `PrometheusURL` (`string`, optional): Endpoint for Prometheus metric queries.
- **Status Extensions**:
  - `LastScaleUpTime` (`*metav1.Time`): Tracks timestamp of the most recent scale-up action.
  - `LastScaleDownTime` (`*metav1.Time`): Tracks timestamp of the most recent scale-down action.
  - `LastScaleAction` (`string`): Most recent action applied (`SCALE_UP`, `SCALE_DOWN`, `MAINTAIN`).
  - `LastGuardrailAction` (`string`): Result of guardrail enforcement (`ACCEPTED`, `CLAMPED`, `REJECTED`).
  - `LastGuardrailReason` (`string`): Detailed human-readable explanation of safety barrier decisions.
  - `FallbackEngaged` (`bool`): Indicates whether reactive HPA fallback was triggered due to an outage or timeout.
  - `Conditions`:
    - `TargetFound`: Deployment found/reachable.
    - `ScalingActive`: Autoscaler actively monitoring.
    - `GuardrailApplied`: Guardrail intercepted, clamped, or rejected a recommendation.
    - `ReasonerHealthy`: External Reasoner reachable and returning valid schema.
- **Printer Columns**: Updated to display `Target`, `Min`, `Max`, `Current`, `Desired`, `Action`, `Fallback`, and `Age` when running `kubectl get aa`.

#### 2. Deterministic Guardrail Engine (`internal/guardrails/guardrails.go`)
The `GuardrailPipeline` evaluates scaling proposals through sequential safety layers:
1. **Absolute Boundary Enforcement**:
   - `ProposedReplicas > MaxReplicas`:
     - If `CurrentReplicas >= MaxReplicas`: Scaling up is **REJECTED** entirely (`Disposition: REJECTED`, target kept at current).
     - If `CurrentReplicas < MaxReplicas`: Clamped down to `MaxReplicas` (`Disposition: CLAMPED`, target set to `MaxReplicas`).
   - `ProposedReplicas < MinReplicas`:
     - If `CurrentReplicas <= MinReplicas`: Scaling down is **REJECTED** entirely (`Disposition: REJECTED`, target kept at current).
     - If `CurrentReplicas > MinReplicas`: Clamped up to `MinReplicas` (`Disposition: CLAMPED`, target set to `MinReplicas`).
2. **Scale-Down Hysteresis Window (Anti-Flapping)**:
   - When candidate action is scale-down (`candidateReplicas < currentReplicas`):
     - Checks elapsed time since `LastScaleUpTime`.
     - If `elapsed < ScaleDownHysteresis` (default 10 minutes):
       - Scaling down is **REJECTED** (`Disposition: REJECTED`, target kept at current).
       - Record explains elapsed vs required cooldown window.
3. **Temporal Rate-Limiting Cooldown Window**:
   - When candidate replicas differ from current:
     - Checks elapsed time since `LastScaleTime`.
     - If `elapsed < CooldownPeriod` (default 60 seconds):
       - Scaling is **REJECTED** (`Disposition: REJECTED`, target kept at current).
       - Record explains remaining cooldown duration.

#### 3. AI Reasoner Client & Reactive HPA Fallback (`internal/reasoner/client.go`)
- **Strict 3-Second SLA**: Calls the external reasoning service (`POST /evaluate-scaling`) with an enforced `3 * time.Second` HTTP timeout.
- **Resilient Fallback Mechanism**:
  - Triggers on:
    1. HTTP call timeouts (`> 3 seconds` or context deadline exceeded).
    2. Connection failure / network partition / service outage.
    3. HTTP non-200 responses (e.g., 500 Internal Server Error, 503 Service Unavailable).
    4. Malformed JSON or invalid schema values (`target_replicas < 1` or empty `action`).
- **Standard Reactive HPA Algorithm**:
  $$\text{desiredReplicas} = \lceil \text{currentReplicas} \times \frac{\text{observedCPU}}{\text{targetCPU}} \rceil$$
  - Incorporates standard $\pm 10\%$ tolerance band to prevent oscillations around the target metric.
  - Clamps output strictly within `[minReplicas, maxReplicas]`.
  - Flags recommendation with `is_fallback: true` and `model_used: "reactive-hpa-fallback"`.

#### 4. Controller Reconcile Loop Integration (`internal/controller/agenticautoscaler_controller.go`)
- Inspects target deployment and gathers cluster telemetry.
- Calls Reasoner client with 3-second timeout.
- Passes recommendation to the deterministic guardrail pipeline.
- Emits structured audit logs (`logger.Info(...)` with `audit_event: "GUARDRAIL_INTERCEPTION"`, `"REASONER_FALLBACK"`, or `"SCALE_EXECUTED"`).
- Emits Kubernetes Events using `record.EventRecorder` (`EventTypeWarning` for guardrail interceptions, outages, and fallbacks; `EventTypeNormal` for scaling executions).
- Scales target deployment replicas via `client-go` when final enforced target differs from current spec.
- Updates custom resource `.status` subresource and conditions.

  ### B. Deterministic Guardrail Pipeline

  In guardrails.go, we built an isolated, pure-logic safety engine (GuardrailPipeline) that enforces invariant checks in
  strict sequential order:

  1. Absolute Boundary Enforcement (minReplicas and maxReplicas Hard Limits):
      • Ceiling Breach (proposedReplicas > maxReplicas):
          • If currentReplicas >= maxReplicas: Scale-up is REJECTED entirely (Disposition: REJECTED), holding replicas at
          current.
          • If currentReplicas < maxReplicas: Clamped down to maxReplicas (Disposition: CLAMPED).
      • Floor Breach (proposedReplicas < minReplicas):
          • If currentReplicas <= minReplicas: Scale-down is REJECTED entirely (Disposition: REJECTED), holding replicas at
          current.
          • If currentReplicas > minReplicas: Clamped up to minReplicas (Disposition: CLAMPED).

  2. Scale-Down Hysteresis Window (Anti-Flapping):
      • When the candidate action is SCALE_DOWN (targetReplicas < currentReplicas):
          • Checks elapsed time since LastScaleUpTime.
          • If elapsed < ScaleDownHysteresis (default 10 minutes), the scale-down is REJECTED (Disposition: REJECTED),
          keeping replicas at current count.

  3. Temporal Rate-Limiting Cooldown Window:
      • If candidate replicas differ from current:
          • Checks elapsed time since LastScaleTime.
          • If elapsed < CooldownPeriod (default 60 seconds), the scaling command is REJECTED (Disposition: REJECTED),
          keeping replicas at current count.

  4. Summary & Interception Audit:
      • Every interception produces a structured record (InterceptionRecord) detailing the invariant violated, original value,
      enforced value, and reason.

  ──────
  ### C. AI Reasoner Client & Reactive HPA Fallback

  In client.go, we implemented the external communication layer:

  1. Strict 3-Second SLA: Reasoner HTTP calls are constrained with an enforced 3 * time.Second HTTP timeout (DefaultTimeout).
  2. Outage & Malformed Schema Detection: Triggers fallback on:
      • Context deadline timeouts (> 3s).
      • Network connection failures / network partitions.
      • Non-200 HTTP responses (HTTP 500, 503, 404, etc.).
      • Malformed JSON responses or invalid schema values (target_replicas < 1 or empty action).
  3. Standard Reactive HPA Fallback Algorithm:

                      ⎡                  observedCPU⎤
    desiredReplicas = │currentReplicas × ───────────│
                      │                   targetCPU │

  • Integrates a standard ±10% tolerance band to suppress jitter around target utilization.
  • Clamps replicas strictly within [minReplicas, maxReplicas].
  • Sets is_fallback: true and model_used: "reactive-hpa-fallback".
  ──────
  ### D. Controller Reconciliation Loop Integration

  In agenticautoscaler_controller.go and main.go:

  1. Full Flow Orchestration:
      • Target deployment inspection → telemetry collection → Reasoner client call (with 3s SLA) → reactive HPA fallback (if
      Reasoner fails) → deterministic guardrail evaluation → client-go deployment patching → Kubernetes event emission and .
      status subresource update.
  2. Structured Audit Logging:
      • Emits structured key-value log entries for every lifecycle event:
          • audit_event: "GUARDRAIL_INTERCEPTION"
          • audit_event: "REASONER_FALLBACK"
          • audit_event: "SCALE_EXECUTED"

  3. Kubernetes Event Recording:
      • Injected record.EventRecorder via mgr.GetEventRecorderFor("agentic-autoscaler-controller").
      • Emits EventTypeWarning events for guardrail interceptions, hysteresis rejections, and reasoner outages.
      • Emits EventTypeNormal events for successful scaling executions.
